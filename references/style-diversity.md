# 图书视频的风格多样性

本系列偏好每条视频有可辨认的视觉变化。用户要求沿用某种风格、品牌或角色时，以用户要求为准。多样性服务书中观点、阅读和情绪，不要求每本书随机换一种画法。

## 先决定内容怎样成为画面

先用一句话说明本片想让观众理解什么，再确定一个贯穿的视觉隐喻或可观察过程。对抽象观点，可以用物体、空间、人物行动或文字关系表达；不要先选特效再把文案塞进去。

| 维度 | 要落实的决定 | 可以产生的实质变化 |
| --- | --- | --- |
| 视觉隐喻与主体 | 谁或什么承担变化，观众如何认出它 | 人物生活、机械路径、建筑光影、织物针脚、自然长卷 |
| 造型与材质 | 轮廓、层次、纹理和边缘怎样画 | 木刻刻线、纸片叠层、布边针孔、平面几何、透明高光 |
| 空间与构图 | 信息在什么空间、从哪里读起 | 单主体留白、连续长卷、台前台后、局部展开、分屏对照 |
| 动作语法 | 哪种可见变化表达本片的动词 | 缝合、压印、搭建、投影移动、路径切换、翻页、递送 |
| 字体与文字角色 | 哪些文字是主角，哪些需要稳定阅读 | 疏朗题字、几何大字、融入实物的文字、清晰独立字幕 |
| 运镜与转场 | 观察位置怎样改变，镜头为何相接 | 视差推进、固定镜头内变化、同形接续、遮挡交接、纸页翻转 |
| 色彩与光线 | 颜色的语义和阅读对比是什么 | 柔和漫反射、定向硬影、有限色印刷、冷暖层次 |

配色、换字体或加颗粒本身不单独算新风格。主体轮廓、空间布局和动作都相同的旧片，即使颜色完全不同，仍视为接近的视觉方案。

## 创作前对照历史

1. 读取当前项目的风格历史；新项目可参考 [系列种子历史](series-history.json)。种子记录来自已完成作品的视觉摘要，只作为比较材料，不表示仓库包含对应成片或私人素材。
2. 看最近 3–5 条，并快速检查候选是否明显重复更早某条的核心隐喻。没有历史时直接围绕内容创作。
3. 在 `storyboard.md` 写明本片方案与最接近旧片的差异。通常至少改变两个核心维度，且至少一个来自主体/隐喻、材质、空间或动作；用户明确要求复用时不强求差异数量。
4. 把变化落成可以检查的决定，例如“透明漂移物体改为哑光实体空间，光与投影代替物体漂移”，不能只写“更高级、更治愈”。
5. 实现最能代表风格且最难解释的一镜，看真实关键帧和动作过程，再完成全片。

可以在内部比较 2–3 个方案，自行选最适合本片的一个；不必为每条片重复要求用户选风格。先检查可读性、素材许可和实现成本。

## 单片内部也要有变化

- 保持同一材质、字体角色和对象身份，按叙事改变景别、主体大小、观察位置或留白；不要每镜都复制同一个圆角卡片。
- 观察、解释、转折、结论可以采用不同信息密度。需要读长句时，运动应安静下来；短问题可以让文字成为主视觉。
- 动作由语义决定：边界要能看出挡住或留下什么，放下要看得到重量离开，重建要看得到一步步形成。
- 画面有起点、变化和落点。节奏不必全片平均，镜头数量与分段时刻不作为固定模板。
- 转场可以来自对象或空间的延续；没有叙事用途的强特效不必添加。主体、材质与运动同时争抢时，先减少装饰。
- 历史片可参考造型方法，不能直接复制旧字幕、固定坐标、整套场景与转场后只替换书名。

## 非穷尽的候选方向

以下是可以继续扩展的方向，既不是必须轮换的目录，也不表示引擎已自动实现。

| 方向 | 适合尝试的画面关系 | 需要实际实现的辨识特征 |
| --- | --- | --- |
| 建筑与光 | 此刻、选择、空间、看见 | 实体遮挡、统一光向、可追踪投影 |
| 织物与线 | 修复、关联、耐心、成长 | 布纹、接缝、逐针显现及线的来路 |
| 木刻或版画 | 经典、行动、对照、印记 | 刻线、反白、套色边界与压印落点 |
| 纸艺或编辑拼贴 | 翻篇、关系、信息重组 | 纸层遮挡、边缘、翻折或重新组合 |
| 机械与路径 | 循环、选择、边界、步骤 | 轨道连通、开合条件、对象连续运动 |
| 微缩空间 | 积累、系统、日常流程 | 统一投影、前后遮挡、局部与整体关联 |
| 水墨或自然长卷 | 流动、季节、经过、变化 | 笔触层次、空间展开、连续过程 |
| 胶片或舞台叙事 | 人物、时代、角色、观察 | 视差或台前台后、光区、明确观察位置 |
| 线条或文字构成 | 连接、比较、概念关系 | 线的生长顺序、稳定锚点、清晰阅读路径 |
| 像素或定格 | 离散状态、试错、步骤 | 实际像素/替换帧设计、有意的阶梯节奏 |

Canvas 可用解析几何、纹理与着色近似材质。需要真实三维、布料或流体模拟时，应另选适合的实现路线并说明依赖；不要用材质名称夸大实际能力。

## 导出后留下可复用记录

在项目内保存风格历史，每个完成版本记录 `book`、`title`、`project`、`family`、`material`、`composition`、`motifs`、`motion`。项目路径使用相对位置，记录视觉摘要即可，不收录音频、成片、私人绝对路径或完整书籍内容。

同一本书仅修人物五官、字幕或音轨的版本沿用一条风格记录，不能算新增风格。另一种完整重做的视觉体系可以另记，并注明与前一版的关系。

种子历史不是永久禁止重复的清单。项目历史需要随新作品更新；旧片曾有的辅助标签、固定镜头或不合当前要求的细节，不因列入历史而成为新片规范。

## 每片的 style.json

新建器会生成空记录；只做方案时也可直接按下面的核心字段建立。额外的运镜、转场、图示或实现说明可自由扩展，不依赖固定风格ID。

```json
{
  "book": "书名", "title": "本片标题", "project": "book-slug-v1", "status": "planned",
  "family": "本片的具体视觉体系",
  "material": ["材质与边缘特征"], "composition": ["空间与阅读路径"],
  "motifs": ["承载内容的主体"], "motion": ["主要动作及落点"],
  "typography": "标题与正文的角色", "palette": ["#FFFFFF", "#304354"],
  "content_fit": "这些对象与动作怎样解释本书观点",
  "compared_with": [{"project": "previous-project", "differences": ["可观察的主体、材质或动作差异"]}]
}
```

`status`使用`planned`、`delivered`或`approved`表达实际状态。`compared_with`在没有可访问历史时可为空，并记录比较范围；不能把未实现的风格写成已通过视觉检查。
