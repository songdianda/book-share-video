# 内容、来源与声音

## 来源边界

- 围绕用户指定书籍。只有书名时优先取得作者原文、出版社试读或合法公开摘录；没有原文时先完成资料与提纲，不假装读过整本书。
- `sources.md` 记录书名、作者、可核对的版本/章节、链接、核验日期、实际阅读范围。未指定版本时不推测页码；译本注明译者，避免混用版本。
- 时间线每句标记 `quote`（逐字短引）、`paraphrase`（观点转述）、`interpretation`（原创解读）或 `example`（原创例子）。短引逐字核对；转述和原创文案不用引号包装成作者原句。
- 本系列不叠加说明性小字。书名作者可进入主文案；确需短引时用正文语气表明“作者在……写道”并核对出处。没有可靠原文时改为原创解读，不靠移除标记掩盖来源差异。
- 现代生活例子是创作者的应用，不伪造书中情节、实验、收益、疾病因果或疗效。不把灵性或励志主张包装成经过验证的医学结论。出处说明放在工程文档。
- 不伪装真实版本书封；可用独立书名排版。图片、音乐、字体分别记录来源，公开视频和上传仍按用户授权执行。

## 60 秒的内容选择

从一个读者能感受到的问题开始，挑一条有原文依据的观点，用可观察动作展开，最后回到一句清楚的收束。允许问答、反转、生活片段、经典原句或连续视觉比喻，不强制统一叙事模板。

参考文案不等于必须逐字用完。优先保留论点与情绪路径，删去重复排比与枝节；术语、关系图或同时看画读字时放慢。常用约 200–280 字、6–9 镜，但以真实可读性和内容为准。字幕淡入、逐字显现与离场不计入完整阅读时间。

## 默认无旁白

以 `timeline.json` 为时间单一来源，同步 `timeline.js`、`segments.json` 与 `captions.srt`。`new_book.py` 可在新项目中一次生成这些文件。后续修改字幕时间或文字时，重新同步派生文件并检查一致性，不让画面和 SRT 各自维护。

使用用户选定的音乐，按 [制作手册](production-workflow.md) 截取/循环到目标时长后做一次淡入淡出。复用已处理的 `score.wav` 时确认时长、采样率和淡入淡出；不要再次叠加同一处理。无旁白模式不调用 `book_audio.py --mux`，该命令需要真实 `voiceover.wav`。

## 用户要求有配音时

只在用户要求/选择声音后启用。先写原创配音稿并生成真实音频，再据实测时长定字幕和镜头，不用字数估算冒充真实音长。用户要求固定总长时先压缩文案或调整真实配音，不能直接裁掉未讲完的句子。

现有本机工具为 `scripts/book_audio.py`；在对应 Python 环境执行：

```bash
python /path/to/book-share-video/scripts/book_audio.py /absolute/project
python /path/to/book-share-video/scripts/book_audio.py /absolute/project --mux
```

输入 `segments.json` 形如：

```json
{"title":"片名","lead":1,"tail":1.5,"gap":0.5,"segments":[{"text":"实际朗读文本","caption":"屏上字幕","kind":"interpretation","audio":"audio/optional-local-voice.wav"}]}
```

`audio` 可省略，由 macOS `say` 的 Tingting 生成样片级声音；不要冒充作者或用户。该工具拒绝覆盖已有时间线和音频，所以有声项目先准备 `segments.json`，不要先用无旁白生成器建立时间线。生成后另建 `timeline.js` 对接画面并校对。`--mux` 混合真实旁白和可选低音量背景音乐，保持旁白清楚，不静默调用付费云服务或索要凭据。
